Junior Backend & Data Developer at Quixta: how I fit.

Hi! This page is for the Quixta hiring team. It maps each point in the job description to work I've actually done, with links to the details. At the end I've listed what I'd still be learning, because I'd rather you hear that from me.

Python, Django and SQL“working knowledge of Django and SQL”

Django: AnimeKyojin is a Django 5 + DRF API on PostgreSQL. It has SimpleJWT auth, indexed models with array fields, and a sync from the AniList GraphQL API.

Python: I built the FastAPI backend for SortCV, with SQLAlchemy models, a repository/service layout and Pydantic schemas.

SQL: I've designed relational schemas in SQLAlchemy, the Django ORM and Spring Data JPA on MySQL.

Build and maintain APIs, migrations and data scripts“backend APIs, database migrations, data scripts”

I built the Clean Milk API on my own: 40+ endpoints on Express and MongoDB, now running in an FAO pilot.

In SortCV, schema changes go through Alembic migrations, for example adding a per-user cv_access column. I've also written seed and maintenance scripts: location data for three states, an admin bootstrap and an expired-OTP cleanup job.

Data processing and cleaning, interest in ML“basic tools like pandas; interest in ML”

SortCV's long-listing step turns messy CV text into a pandas DataFrame, then cleans and filters it by experience, degree and skills before exporting it.

The short-listing step ranks candidates with Sentence-BERT embeddings, KeyBERT and weighted cosine similarity. On the MongoDB side, I write multi-stage aggregation pipelines for analytics dashboards.

AI tools such as Claude and Cursor“experience with AI tools”

I use Claude and Cursor every day. I use them to scaffold modules, trace bugs through unfamiliar code, draft tests and review my diffs before I push. I also run local models in LM Studio to experiment.

I treat AI output like a teammate's pull request: I read it, test it and take responsibility for it.

Work closely with frontend teammates“solid backend foundation, collaborate with frontend”

I've been that frontend teammate. On WISH (87 commits), SOMA and the UNODC portal I consumed other people's APIs every day.

So on my own backend I ship Swagger docs with every endpoint and keep one consistent error shape. That way the web and mobile apps aren't blocked on me.

Fix bugs, write tests, document your work“debugging, testing, documentation”

I've done a lot of bug fixing, including several QA rounds on WISH, the UNODC portal and SOMA before release. I document APIs in OpenAPI and keep my commit history readable.

Honest gap: automated testing is my weakest area. pytest is set up in SortCV, but I haven't yet worked on a team with a strong testing culture. I'd like to.
